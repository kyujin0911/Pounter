# 디자인 레퍼런스와 화면 명세

갱신일: 2026-10-13. 상태: Navigation 목적지/이동 구현 / 아이콘 기반 디자인 규칙 작성 / 디자인 적용·현장 사용성 검증 대기.

제품 범위·지원 조건·보존·인수 기준은 [PRD](../PRD.md), 검출기는 [자동 계수 설계](auto_counting.md)를 참조한다. S-01~S-05는 기능/상태 구분이다. 아래 Navigation 목적지는 사용자 요청에 따라 분리하며 별도 Activity·모듈은 도입하지 않는다.

모든 외부 레퍼런스는 2026-10-12 공개 설명/이미지 조사다. 앱 설치·사용자 사진으로 계수·실행 속도 검증을 하지 않았다. AI 모델·Hough·타원 검출·분할 등 내부 알고리즘을 화면만으로 확정하지 않는다. 브랜드·에셋을 복제하지 않고 자체 색상·컴포넌트를 사용한다.

공통적으로 참고할 구조는 개별 위치 후보→총개수→사람 보정→결과 보존이다. 원형 표시를 HoughCircles 채택 근거로 사용하지 않는다. 우리 앱의 검출 엔진은 사용자 채택 비AI 접근을 따른다.

## 일관된 디자인 방향

사진·개수·현재 상태가 먼저 보이는 검수 도구. 복잡한 보고서/설정 패널 대신 핵심 흐름을 완료하는 조작을 제공한다.

색상·글꼴·형태·간격·컴포넌트 적용 기준은 2026-10-13 사용자 첨부 아이콘과 공식 가이드로 작성한 [디자인 규칙](design_system.md)을 따른다. 이전 임시 팔레트·글꼴 제안은 이 문서로 대체한다. 공식 기준과 Pounter 자체 선택, 규칙 작성과 앱 적용·검증을 구분한다.

색상 대비·표시 밀도·작은 단면 가림을 실제 화면으로 검증한 뒤 확정한다. 자동 원형/수동 사각형이라는 기존 표시 예시는 구현 스냅샷이며 최신 표시 형태의 확정 제약이 아니다.

## 화면·상태 명세

### S-01 시작/기록

새 사진 촬영·사진 선택을 주요 동작으로 둔다. 진행 중 기록 이어가기와 사용자 확인 완료 기록을 구분한다. 기록이 없으면 정면·전체 단면·가림 확인 안내. 날짜·사진 미리보기·개수·상태로 기록을 구별하는 안을 검증하며 이름 입력은 필수가 아니다.

### S-02 사진 확인

사진을 크게 표시하고 전체 단면 식별 여부·가장자리 잘림을 확인한다. 기본은 사진 전체, 배경 자르기는 선택. 촬영 안내: '한 묶음의 모든 단면이 보이도록 정면에서 촬영하세요. 끝이 앞뒤로 불규칙해도 각 단면이 구별돼야 합니다. 보이지 않는 단면이 있으면 촬영 위치를 바꿔주세요.'

취소/다른 사진은 PRD의 기존 작업 보존 정책을 따른다. 자르기가 기존 보정을 초기화하는 경우 명시적 확인. 분석 버튼과 재촬영/재선택 제공. '완전 가림 없음'을 자동 판정했다고 표시하지 않는다.

### S-03 분석 중

현재 사진과 진행 상태·취소를 표시한다. 실제 진행률을 계산할 수 없으면 허위 백분율을 사용하지 않는다. 저장 시작 후 중복 입력·취소를 차단하는 상태를 구분한다. 실패 시 원인을 이해할 수 있는 문구와 재시도/사진 교체를 제공한다.

### S-04 검토/보정

상단: 현재 개수·확인 전 상태. 상세에서 자동 개수와 추가/제외 내역 구분. 가운데: 사진과 표시. 주요 도구: 이동·추가·제외·되돌리기·번호·표시 크기. 하단: 사용자 확인 완료 저장.

- 확대·이동과 보정 탭의 제스처를 구분하고 현재 모드를 문구·선택 상태로 표시.
- 표시가 겹치면 확대와 선택 목록을 제공. 목록 선택을 사진 위치와 연결.
- 사진을 이동하거나 표시를 보정해도 이미 검토한 위치를 잃지 않도록 안정적인 식별 유지.
- 불규칙 작은 파이프에서는 들어간 단면의 누락과 돌출 단면 주변 중복을 검토할 수 있게 표시를 작게 유지.
- 0개는 '검출된 파이프가 없습니다'. 없음으로 자동 확정하지 않고 재시도/재촬영/수동 보정 경로.
- 검출 강도 슬라이더는 기본 제공하지 않음. 기하학 점수를 확률/정확도로 표시하지 않음.
- 영역별 확인/검토 진행 표시는 사용 실험에서 필요성이 확인되면 별도 채택. 기본 기능으로 확정하지 않음.

### S-05 사용자 확인 완료 기록

사진·표시·최종 개수·확인 시각을 읽기 전용으로 보여준다. '사용자가 확인했다'는 뜻이며 시스템이 정확성을 인증했다는 뜻이 아니다. 재열기·삭제를 제공한다. 삭제는 되돌릴 수 없음과 원본 갤러리 유지 안내 후 확인한다. 오확정 정정은 PRD의 임시 정책을 따른다.

## 작은 화면·접근성·실패 표시

- 작은 화면과 글꼴200%에서 도구를 줄바꿈하고 주요 조작에 스크롤로 도달 가능하게 한다. 가능한 사진 검토 영역을 실제 기기에서 평가.
- 시스템 바·화면 잘림·IME inset 반영. 기본 흐름에는 텍스트 입력 없음.
- 시스템 다크 모드 지원, 사진의 밝은/어두운 영역 모두에서 표시 대비 확인.
- TalkBack에 개수·모드·저장/오류 상태·조작 이름 제공. 표시 선택 목록과 추가 위치 조절 등 대체 입력 경로 검토.
- 조작 경로가 존재한다는 사실만으로 시각적 단면 검수의 접근성을 충족했다고 보고하지 않음. 실제 작업 수행 가능성 별도 확인.
- 실패·미저장·부분 결과를 색만으로 전달하지 않음. 저장 실패 시 보정을 잃지 않고 재시도할 수 있어야 함.

관련 검증과 완료 판단은 [PRD 인수 조건](../PRD.md#5-인수-조건)에 둔다. 과거 합성 이미지 화면 확인은 [검증 이력](verification.md)에만 남기며 새 화면 검증으로 확대하지 않는다.

## Navigation 목적지와 이동 규칙

2026-10-12 사용자 승인에 따른 구현. Navigation Compose 2.9.8의 NavHost/NavController와 직렬화 가능한 타입 경로를 사용한다. 기존 Kotlin 2.1.21·Compose·단일 모듈을 유지하며 Navigation 3의 별도 백 스택/상태 체계 도입은 이번 범위에서 선택하지 않았다. 빌드 호환성과 실행 검증은 검증 이력 참조.

| 목적지 | 기능 상태 | 입력 |
|---|---|---|
| HomeRoute | S-01 시작·기록 목록 | 없음 |
| WorkRoute | S-02~S-04 사진 확인·영역·분석·보정 | taskId만 전달 |
| RecordRoute | S-05 읽기 전용 기록 | taskId만 전달 |

- 각 entry의 CountViewModel은 경로의 taskId를 SavedStateHandle에서 읽고 Repository에서 복원한다. 전역 선택 작업 ID를 별도로 복원하지 않는다. NavController는 UI에만 둔다.
- 목록에서 저장 상태에 따라 작업/기록 목적지로 이동한다. 경로 종류와 실제 확정 상태가 다르면 올바른 목적지로 교체하며 기록 화면은 전환 중에도 편집 도구를 제공하지 않는다.
- 새 사진 가져오기 성공 후에만 새 ID로 작업 화면을 연다. 이전 작업은 저장소에 유지하고 이전 상세 목적지는 제거한다. Picker/카메라 취소·읽기 실패는 원래 목적지를 유지한다.
- 일반 뒤로 가기는 목록으로 복귀한다. 분석 중 첫 뒤로 가기는 분석을 취소하고 현재 화면을 유지한다. 불가역 저장 중에는 이동을 막는다. 미저장 변경이 있으면 이동 대신 저장 재시도를 안내한다.
- 완료 저장 성공 후 HomeRoute 위의 편집 entry를 제거하고 RecordRoute를 연다. 뒤로 가기로 완료 전 편집 화면이 다시 나타나지 않는다. 삭제도 성공 후에만 목록으로 복귀한다.
- 없는/삭제된 ID는 다른 작업이나 홈 화면으로 오인하지 않게 오류와 목록 복귀 버튼을 제공한다. 사진 미리보기만 실패하면 작업 데이터와 표시를 유지한다.
- 저장 실패는 보정 내용을 화면과 pendingSave에 유지한다. 완료 실패는 확인 완료로 표시하지 않는다. 재시도는 같은 변경을 저장한다.
- 회전/Activity 재생성은 entry ViewModel 또는 Navigation 저장 상태로 이어간다. OS 프로세스 종료 후 복원은 저장된 back stack과 ID, Room 데이터, SavedStateHandle의 미저장 스냅샷을 사용한다. 중단된 연산은 자동 재개하지 않는다.
- SavedStateHandle은 OS가 상태를 저장한 경우의 복원 수단이다. 강제 종료·앱 제거·상태 저장 전 비정상 종료에서 미저장 스냅샷 보존을 보장하지 않는다. 강제 종료 후 재실행은 목록에서 마지막 영속 작업을 재열어 확인한다.

공식 근거: [그래프·타입 안전 경로](https://developer.android.com/guide/navigation/design), [Navigation 릴리스](https://developer.android.com/jetpack/androidx/releases/navigation). 실제 검증 범위는 [검증 이력](verification.md)을 따른다.
