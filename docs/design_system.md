# Pounter 디자인 시스템

갱신일: 2026-10-13. 버전: 설계 초안 0.2. 상태: 토큰·컴포넌트·상태·화면 패턴 설계 / 앱 적용·화면 검증 대기.

이 문서는 Pounter의 UI 디자인·구현·리뷰 기준이다. 제품 범위와 보존 정책은 [PRD](../PRD.md), 목적지·이동·화면 상태는 [화면 명세](design_spec.md)가 우선한다. 기존 화면 명세의 임시 색상·타이포그래피 제안은 이 규칙으로 대체한다. 규칙 작성은 구현 완료나 사용성 검증을 뜻하지 않는다.

재사용 판단·Modifier·값/이벤트·슬롯·상태 소유의 상세 기준과 최신 컴포넌트 서명은 [Compose 컴포넌트 규칙](compose_components.md)을 따른다. 기존 업무 역할은 유지하며 StatusLabel의 값 중심 계약과 NoticeCard의 공통 컨테이너를 이 문서의 컴포넌트 설계에 추가한다.

[디자인 보드](design_system_board.html)에서 라이트·다크의 홈·보정·완료 패턴과 저장 실패 변형을 비교할 수 있다. 보드는 가상 자료로 만든 설계 시안이며 Android 실행 화면·실제 검출 결과가 아니다.

## 1. 근거와 디자인 판단

2026-10-13 공식 페이지를 조회했다. 아래 공식 원칙과 Pounter 자체 선택을 구분한다.

| 공식 근거 | 확인한 원칙 | Pounter에 적용할 판단 |
|---|---|---|
| [Android Layout basics](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-basics) | 안전 영역, 일관된 정렬·간격, 조작 접근성, 화면 크기 대응 | 사진·현재 개수·보정 도구를 한 작업 단위로 묶고 장문의 안내가 사진을 밀어내지 않게 한다 |
| [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3) | 색상·글꼴·형태를 테마로 제공하고 기본 Material 컴포넌트를 사용 | 아래 브랜드 팔레트와 글꼴·형태를 MaterialTheme에 연결한다. 디자인만을 위한 의존성 업그레이드는 하지 않는다 |
| [Android 접근성](https://developer.android.com/guide/topics/ui/accessibility/apps) | 작은 글자 대비 4.5:1, 큰 글자 대비 3:1, 최소 48×48dp 터치 영역 | 활성 텍스트는 크기에 관계없이 4.5:1을 내부 목표로 삼고 주요 버튼 높이는 최소 56dp로 둔다 |
| [Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) | 기본 컴포넌트의 의미·터치 영역 지원, 맞춤 UI는 추가 고려 필요 | Canvas의 작은 표시와 조작 버튼의 터치 영역을 구분하고 목록·위치 조절 대체 입력을 유지한다 |

Material 색상 역할·글꼴 체계 참고: [Color roles](https://m3.material.io/styles/color/roles), [Applying type](https://m3.material.io/styles/typography/applying-type). 해당 Material 사이트 본문은 이번 브라우저에서 추출되지 않아, 세부 기준은 위 Android 공식 Compose 문서에서 확인했다. 수치·팔레트·배치의 자체 선택을 Google의 필수 규칙으로 표현하지 않는다.

## 2. 브랜드 해석과 우선순위

사용자 첨부 아이콘에서 관찰한 요소는 선명한 파란 바탕, 흰색 원형 파이프 세 개, 하늘색 중심점, 오른쪽 아래의 확대경 같은 형태다. '단면을 찾아 확인한다'는 제품 해석은 디자인 판단이며 사용자 조사 결과가 아니다.

첨부 JPEG의 파란 배경·하늘색 중심·흰색 윤곽 일부 영역을 샘플링한 RGB 중앙값은 각각 `#164EE2`, `#A1E1FD`, `#FEFEFE`였다. 압축·질감·영역 선택에 영향을 받으므로 원본 브랜드 HEX와 동일하다고 주장하지 않는다. 아래 UI 색상은 이를 출발점으로 조정한 자체 팔레트이며 자동 생성된 Material tonal palette가 아니다.

1. 사진에서 무엇을 세었는지 확인할 수 있어야 한다.
2. 현재 개수, 보정 모드, 저장 상태를 즉시 구별할 수 있어야 한다.
3. 다음 주요 동작을 쉽게 찾고 실행할 수 있어야 한다.
4. 색·형태의 일관성으로 브랜드를 전달한다.

청색은 주요 동작과 선택을, 하늘색은 작은 보조 포인트를 맡는다. 넓은 배경은 중립색으로 둔다. 로고의 원형은 모서리·작은 상태 표시로 번역하되 카드 전체를 원형으로 만들거나 화면에 큰 로고를 반복하지 않는다. 로고의 세 원을 근거로 새 3단계 흐름이나 검출 알고리즘을 만들지 않는다.

## 4. 글꼴·간격·형태

시스템 기본 글꼴과 한국어 fallback을 사용한다. 글자 크기는 sp, 레이아웃은 dp이며 굵기와 행간도 테마에 둔다. 아래는 Pounter 선택값이고 Material 기본 수치와 항상 같지는 않다.

| 역할 | 크기 / 행간 | 굵기 | 적용 |
|---|---|---|---|
| displaySmall | 40 / 48sp | Bold | 현재 개수 |
| headlineSmall | 24 / 32sp | SemiBold | 홈의 주요 시작 제목 |
| titleLarge | 22 / 28sp | SemiBold | 화면·섹션 제목 |
| titleMedium | 16 / 24sp | SemiBold | 기록 제목·도구 그룹 |
| bodyLarge | 16 / 24sp | Normal | 주요 안내 |
| bodyMedium | 14 / 20sp | Normal | 날짜·보조 설명 |
| labelLarge | 14 / 20sp | SemiBold | 버튼·모드 이름 |

중요한 상태·오류·보존 안내를 12sp 이하로 축소하지 않는다. 숫자에는 '개' 단위와 '현재 개수' 설명을 제공한다. 확인 전 개수를 최종 결과처럼 강조하지 않는다. 큰 글꼴에서 날짜·단위·확정 버튼은 줄바꿈하며 중요한 문구에 말줄임을 사용하지 않는다.

- 간격 척도: 4 / 8 / 12 / 16 / 24 / 32dp. 일반 화면 바깥 여백 16dp, 카드 내부 16dp, 주요 시작 영역 20dp. 관련 요소 8dp, 그룹 16dp, 큰 섹션 24dp를 기본값으로 둔다.
- Shape: extraSmall 4dp, small 8dp, medium 12dp, large 16dp, extraLarge 24dp. 기록 카드 medium, 사진/주요 시작 영역 large, 대화상자 extraLarge. 버튼은 Material 기본 둥근 형태를 사용한다.
- 주요 버튼 높이 최소 56dp, 기타 조작 터치 영역 최소 48×48dp. 고정 높이로 큰 글꼴을 자르지 않는다. 작은 아이콘의 시각 크기와 터치 크기를 구분한다.
- 일반 카드는 큰 그림자 대신 표면 색과 여백으로 구분한다. 숫자·로고에 광택·질감·그라데이션을 추가하지 않는다.

## 5. 컴포넌트·상태·문구

| 상황 | 규칙 |
|---|---|
| 다음 주요 동작 | 화면 상태별 Filled Button 한 개를 시각적 주역으로 둔다. 홈은 '사진 촬영', 사진 확인은 현재 제공 가능한 시작 동작, 보정은 'N개 확인하고 저장' |
| 대안 동작 | '사진 선택', '다시 촬영'은 Outlined/Text Button. 영역·번호·확대는 도구 그룹에 둔다 |
| 보정 모드 | 이동·추가·제외를 선택 상태와 문구로 구분. 되돌리기는 별도 조작. 원본 파이프 삭제처럼 보이지 않도록 '표시 제외' 의미를 알린다 |
| 저장 중 | 주요 입력 잠금과 '저장 중' 표시. 성공 전 완료 문구·완료 화면 이동 금지 |
| 저장 실패 | 지속 오류 영역에 보정 유지 여부와 '저장 재시도'를 제공. 잠깐 뜨는 알림만으로 전달하지 않는다 |
| 자동 계수 미제공 | '자동 계수 · 검증 대기'와 현재 가능한 수동 기능을 설명. 회색 비활성 버튼만으로 이유를 대신하지 않는다 |
| 확인 완료 | '사용자 확인 완료'로 표현. 정확도 인증·자동 성공으로 쓰지 않는다 |
| 삭제 | 주 작업과 분리한 오류색 Text Button과 확인 대화상자. 파괴적 동작을 하늘색/청색 주요 버튼처럼 강조하지 않는다 |

오류 이외 안내를 모두 errorContainer로 칠하지 않는다. 안내·로딩·미저장·오류의 의미를 실제 상태에 맞춰 구분한다. 버튼 설명은 '대상 + 동작', 오류는 '문제 + 보존 상태 + 다음 조치'로 쓴다. 현재 코드의 Action·저장 성공 판정·Dialog 보호 조건을 문구 변경으로 우회하지 않는다.

움직임은 선택·열기·처리 상태를 설명할 때만 사용한다. 숫자 보정마다 사진이 튀거나 목록이 자동 이동하지 않게 한다. 측정하지 않은 진행률·남은 시간을 표시하지 않는다. 새 Expressive API·모션 라이브러리는 이 문서만으로 도입하지 않는다.

## 6. 사진 표시와 화면별 적용

표시의 목적은 단면을 가리지 않고 위치를 알려주는 것이다. 로고의 두꺼운 흰색 링을 검출 마커에 그대로 복제하지 않는다. 작은 중심점·외곽선·번호 크기는 밀집 사진과 확대 상태에서 검증 후 선택한다. 밝은/어두운 사진 모두에서 이중 테두리를 평가하고, 자동·수동 출처는 모양 또는 목록 문구를 함께 제공한다. 하늘색은 사진 위에서 대비가 보장되지 않으므로 단독 표시색으로 확정하지 않는다.

| 화면 | 적용할 배치 | 피할 배치 |
|---|---|---|
| 홈 S-01 | 작은 브랜드 표시/제목 → 간결한 촬영 안내·두 입력 동작 → 검증 대기 안내 → 진행 중/완료 기록 | 장문의 브랜드 카드·큰 로고·중복 경고로 기록을 밀어내기 |
| 사진 확인 S-02 | 개수보다 사진과 촬영 적합성 확인을 우선. 선택적 영역과 시작 동작 제공 | 미분석 0을 최종 계수처럼 표현, 영역 지정 강제 |
| 분석 S-03 | 현재 사진·처리 문구·허용되는 취소를 함께 표시 | 허위 %나 성공 애니메이션 |
| 검토 S-04 | 개수/확인 전 요약 → 가장 큰 사진 영역 → 보정 모드/되돌리기 → 확인 저장. 번호·영역·사진 교체는 보조 그룹 | 도구를 한 줄에 압축, 사진 위에 장문의 안내를 덮기 |
| 기록 S-05 | 최종 개수·사용자 확인 완료·시각 → 사진/표시. 편집 도구 없이 기록 삭제 제공 | 완료 기록에 수정 가능한 것처럼 보이는 조작 |

일반 세로 화면에서 확정 동작을 하단에 두는 안을 우선 평가한다. 작은 높이·글꼴 200%에서는 고정 하단바가 사진/도구를 압박하면 스크롤 가능한 배치로 전환한다. 사진을 항상 340dp로 고정하지 않고 가용 공간·방향·사진 비율에 대응한다. 사진 전체를 맞춰 표시하는 초기 상태와 확대/이동을 구분하고 보정마다 확대 위치를 리셋하지 않는다.

시스템 바·컷아웃·제스처 영역을 반영한다. 세 목적지를 이유 없이 하단 내비게이션 세 탭으로 바꾸지 않는다. 작은 화면에서 먼저 핵심 흐름을 검증하며, 태블릿·새 목적지·썸네일 데이터 계층을 이번 규칙으로 추가 승인하지 않는다.

## 7. 구현 연결과 적용 순서

1. 테마에서 위 ColorScheme·Typography·Shapes를 선언한다. 우선 테마와 기존 컴포넌트를 사용하고 별도 디자인 시스템 프레임워크·모듈은 만들지 않는다.
2. 홈·작업·기록 화면의 글자·표면·버튼을 역할 토큰으로 연결한다. 사진 마커 등 특수 시각 값은 의미가 있는 이름으로 따로 관리한다. 상태·저장·검출 계산과 디자인 값을 섞지 않는다.
3. 홈 안내의 밀도를 낮추고, 사진·보정·확정 동작의 접근성을 개선한다. 오류·보존 설명은 삭제하지 않는다.
4. 앱 실행 화면과 접근성을 검증한 뒤 적용 결과를 [검증 이력](verification.md)에 기록한다. 적용만으로 현장 효용이나 검출 성능을 달성했다고 보고하지 않는다.

현재 로컬 경로는 `ui/PipeTheme.kt`, `ui/PipeApp.kt`, `ui/PhotoPanel.kt`다. 저장된 origin/main에는 `core/ui/theme`와 `feature/home`, `feature/count`, `feature/record`, `feature/shared`로 분리된 후속 구조가 있다. 구현 시 실제 기준 브랜치에서 경로를 확인하고 같은 테마를 중복 작성하지 않는다. 이번 문서는 로컬 main e30d20c에서 작성했으며 원격 서버 최신 상태는 조회하지 않았다.

Figma는 필수가 아니다. 협업·여러 시안 비교가 필요하면 파일의 색상·글꼴·형태를 이 규칙과 같은 역할 이름으로 관리하고 light/dark 및 입력/보정/저장 실패/완료 변형을 포함한다. 첨부 JPEG의 UI 재사용용 에셋 변환이나 런처 아이콘 적용은 이 규칙 작성과 구분한다. 사용자 이미지와 현장 사진을 외부 서비스로 전송하거나 커밋하지 않는다.

## 8. 완료 조건과 검증 경계

문서 작성 검증: 로컬 링크, 대체 관계, 공식/자체 기준 구분, 색상 쌍 대비 계산, diff 검사. 아래 실행 항목은 앱 적용 후 확인하며 지금 통과한 것으로 취급하지 않는다.

2026-10-13 계산 결과: 위 팔레트의 on-color/배경, 기본·보조 글자/표면, 역색상 전경/표면을 라이트·다크 합계 54쌍으로 검사했다. sRGB 선형화 후 상대 휘도 대비 `(밝은 휘도 + 0.05) / (어두운 휘도 + 0.05)`로 계산했으며 최솟값은 5.45:1(다크 inversePrimary/inverseSurface), 4.5:1 미달은 0쌍이다. 이는 지정 HEX의 불투명 색상 계산이며 렌더링·주변 밝기·사진 위 표시·접근성 실행 검증이 아니다.

- 라이트·다크에서 활성 글자/컨테이너 쌍이 내부 목표 4.5:1 이상. 반투명 상태·pressed·disabled·사진 위 표시는 합성 결과로 별도 확인한다.
- 최소 48×48dp 조작 영역과 겹치지 않는 입력. 아이콘 버튼은 의미 있는 이름, 글자와 중복된 장식 아이콘은 중복 낭독 제외.
- 360dp 폭의 작은 화면, 가로, 글꼴 100%/200%에서 주요 동작 도달·문구 미잘림·사진 가림 확인. 대표 S22+에서 밝은 환경 가독성과 밀집 단면 검수 별도 확인.
- TalkBack에 개수·선택 모드·처리/저장 결과·오류·재시도 제공. 표시 목록·위치 조절 사용 가능성과 실제 사진 검수 수행 가능성을 따로 평가.
- 빈 기록·미분석·검출 0·분석/저장 중·미저장·저장 실패·사진 읽기 실패·확인 완료에서 동작과 문구 일치.
- 사진/표시 좌표, 유효 표시에서 계산하는 개수, 되돌리기, 저장 실패 보존, 읽기 전용 기록, Navigation 복원을 보존한다.

적용 시 관련 빌드·Lint·단위/기기 테스트와 실제 화면 관찰을 구분해 기록한다. 초기에는 기본 사용성과 브랜드 토큰을 정리하고, 자동 검출 구현·독립 실사진 평가 이후 마커 밀도와 보정 도구를 다시 조정한다.

## 9. 시스템 구조와 선택 이유

디자인 목표는 '단면을 확인하는 데 집중하고, 변경이 보존됐는지 확신하게 하는 도구'다. 검수 담당자의 사진 대조 작업이 중심이며 장갑 사용·야외 사용 빈도·한 손 조작 선호는 확인되지 않은 가정이다. 이를 이유로 터치 정확도나 현장 성과를 확정하지 않는다.

| 접근 | 장점 | 비용/판단 |
|---|---|---|
| 기본 Material 그대로 | 구현이 빠르고 기본 접근성을 활용 | 기본색·일반 카드만으로 검수 상태의 우선순위가 약함 |
| Material 기반 브랜드·업무 컴포넌트 | 익숙한 조작에 Pounter 색과 사진 검수 패턴을 연결 | 채택 방향. 작은 컴포넌트 집합과 상태표로 충분 |
| 전면 맞춤 UI/복잡한 Expressive 모션 | 강한 시각 개성 | 사진 검수를 방해하거나 접근성을 다시 구현할 비용. 현재 선택하지 않음 |

시스템은 세 층으로 둔다. 기초 값은 3~4절의 토큰, 의미 있는 UI 단위는 아래 컴포넌트, 화면은 그 조합이다. 모든 Text/Button을 전용 래퍼로 만들거나 5단계 Atomic 계층을 강제하지 않는다. 토큰은 테마에서 공유하고 컴포넌트는 반복되는 업무 의미가 있을 때 추출한다. Repository·ViewModel은 데이터와 동작을, UI는 전달받은 상태의 표현을 맡는다.

## 10. 의미 토큰과 컴포넌트 계약

Material 역할을 아래 업무 의미에 매핑한다. 별도 브랜드 이름의 색을 화면마다 복제하지 않는다.

| 의미 | 대응 | 사용 규칙 |
|---|---|---|
| action.primary | primary / onPrimary | 다음 주요 동작 |
| selection.active | primaryContainer / onPrimaryContainer | 선택한 모드. 테두리/체크/문구도 제공 |
| content.default | onSurface | 상태·현재 개수 설명 |
| content.supporting | onSurfaceVariant | 날짜·부가 설명. 필수 오류는 여기에 숨기지 않음 |
| surface.record | surfaceContainerLow / onSurface | 목록의 일반 기록 |
| surface.notice | surfaceContainer / onSurface | 중립 안내·미제공 이유 |
| surface.failure | errorContainer / onErrorContainer | 지속 오류·재시도 |
| status.confirmed | secondaryContainer / onSecondaryContainer | 체크 아이콘 + '사용자 확인 완료'. 정확도 인증 아님 |
| photo.canvas | #111827 | 사진의 빈 여백. 사진 자체 필터 없음 |
| photo.marker | 출처·선택·번호용 별도 값 | 브랜드색 강제보다 단면 식별 우선. 실사진 검증 전 임시 값 |

아래 이름은 설계용 역할이다. 기존 동등 컴포넌트가 있으면 확장하고 중복 파일을 만들지 않는다. 컴포넌트는 상태·콜백·modifier를 받으며 직접 파일/DB/Navigation을 처리하지 않는다.

| 컴포넌트 | 구성/입력 | 변형·행동·제약 |
|---|---|---|
| TaskHeader | 제목, 부가 날짜, 목록 복귀 | 제목 titleLarge, 복귀 접근 영역 48dp. 작업 보호 조건은 기존 상태에서 받음 |
| PhotoInputCard | 제목, 짧은 촬영 조건, 촬영/선택 콜백 | 시작/가져오는 중/입력 오류. 기본 안내 2문장 이내를 목표로 하되 글꼴 확대 시 자연 줄바꿈 |
| RecordCard | 날짜, 개수의 유무, 진행/완료 상태, 열기 | 전체 카드 하나의 열기 동작. 미분석은 '— · 분석 전', 분석 0은 '0개'. 둘을 동일 취급하지 않음 |
| CountSummary | 현재 개수, 분석 여부, 확인 여부, 저장 상태 | 미분석/확인 전/완료. 0~300 목표 근처에서도 단위와 상태를 함께 읽음. 분석 시간은 보조 정보 |
| StatusLabel | TaskStatus 값, 보조 아이콘 | 분석 전·확인 전·사용자 확인 완료. 홈 진행 중은 카드 문맥 문구. 비조작 상태 라벨은 탭 가능한 Chip처럼 만들지 않음 |
| NoticeCard | 정보/오류 의미, 선택 제목·action 슬롯, 본문 슬롯 | 로딩·검증 대기·오류·복구의 공통 표면. 업무 문구·이벤트·보호 조건은 소비자가 결정 |
| PhotoViewport | 사진, 표시, 영역, 확대 위치 | 불러오는 중/읽기 실패/사진 있음. 실패에도 개수·표시 데이터를 폐기하지 않음 |
| CorrectionToolbar | 선택 모드, 되돌리기 가능 여부, 편집 가능 여부 | 이동·추가·제외 중 하나 선택. 48dp 터치 영역, 8dp 간격. 폭이 부족하면 되돌리기 별도 행 |
| PhotoDisplayTools | 번호 상태, 확대/축소/전체 보기/표시 목록 | 선택 상태를 보정 모드와 혼동하지 않게 분리. 원래 대체 입력 기능 유지 |
| OperationNotice | 작업 의미, 메시지, 허용된 취소 | 가져오기/분석/저장. 애니메이션만으로 상태 설명하지 않음 |
| RecoveryNotice | 문제, 보존 상태, 재시도, 복귀 가능 여부 | 저장 실패는 사진 근처와 도구보다 앞서 읽히게 표시. 완료 처리 대신 재시도 |
| ConfirmAction | 개수, 사용 가능 여부, 저장 중 여부 | 최소 56dp. 'N개 확인하고 확정' → 확인 대화상자 → 저장 중. 앱의 보호 조건을 그대로 반영 |
| DestructiveDialog | 대상, 삭제 영향, 취소/삭제 | 완료 사진의 앱 내부 사본과 기록 삭제를 설명. 취소를 기본 탈출 경로로 제공 |

버튼 pressed/focus/disabled는 설치된 Material 기본 상태 표현을 우선한다. 도구가 잠겼으면 선택한 모드는 남기되 새 동작을 막고 잠긴 이유를 표시한다. 장애나 상태 변화로 요소를 숨길 때 주변 사진·스크롤 위치를 불필요하게 바꾸지 않는다. 중요한 완료·오류 정보는 Snackbar만으로 전달하지 않는다.

## 11. 화면 상태와 조작의 우선순위

아래는 UI 표현 계약이며 새로운 상태 저장소나 상태 enum 도입 요구가 아니다. 기존 상태 조합을 매핑한다.

| 상태 | 개수/상태 표현 | 주요 동작 | 잠금·보존 |
|---|---|---|---|
| 사진 입력 전 | 기록 목록과 촬영 안내 | 사진 촬영 | 취소 시 기존 기록 유지 |
| 가져오는 중 | '사진을 불러오는 중' | 중복 입력 차단 | 실패 시 원래 화면에서 재선택 |
| 사진 확인/미분석 | '— / 분석 전' | 현재는 수동 표시 시작. 자동은 검증 대기 안내 | 사진 적합성·선택 영역 확인 |
| 분석 중 | '분석 중', 기존 표시가 있으면 이전 결과라고 구분 | 분석 취소 | 오래된 결과로 현재 사진을 덮어쓰지 않음 |
| 검토/저장된 보정 | 'N개 / 확인 전' | N개 확인하고 확정 | 추가·제외·되돌리기 허용 조건 유지 |
| 0개 검토 | '0개 / 확인 전', 자동 결과면 '검출된 파이프가 없습니다' | 수동 보정 또는 재촬영 | 0을 오류나 완료로 자동 변환하지 않음. 확정 조건은 기존 로직 유지 |
| 변경 저장 중 | 개수 유지, '변경 사항 저장 중' | 중복 조작 차단 | 저장 전 완료 배지 없음 |
| 변경 저장 실패 | '저장되지 않은 변경' + 현재 보정 개수 | 저장 재시도 | 확정/편집/이동 조건을 약화하지 않음 |
| 확정 저장 중 | '확정 기록 저장 중' | 중복 확정 차단 | 결과 성공 전 완료 화면 이동 없음 |
| 확인 완료 | 'N개 / 사용자 확인 완료' + 시각 | 목록으로 | 읽기 전용, 수정 모드 숨김 |
| 사진 읽기 실패 | '사진을 표시할 수 없습니다' + 기록 상태/개수 유지 | 제공 가능한 복구/목록 복귀 | 가짜 사진·빈 0개로 대체하지 않음 |

우선순위는 복구가 필요한 오류 → 진행 중 연산 → 업무 정보 → 주 조작 → 보조 조작이다. 오류를 강조한다고 사진을 완전히 가리는 전체 화면을 기본값으로 쓰지 않는다. 자동 기능 제공 전의 화면과 제공 이후의 화면은 같은 시안에서 성공한 자동 검출로 섞지 않는다.

## 12. 화면 패턴의 상세 규격

홈은 작은 브랜드 제목, 중립색 시작 카드, 파란 촬영 버튼/윤곽선 사진 선택 버튼, 한 묶음 촬영 조건, 중립 검증 대기 안내, 기록 순서다. 기존 넓은 파란 배경 카드에서 흰색/중립 표면 중심으로 조정해 주요 버튼의 강조를 살린다. 기록 정렬·필터·썸네일은 새 데이터 동작을 추가하지 않고 기존 순서를 유지한다.

보정 화면은 제목/복귀, 개수와 확인 전 라벨, 사진, 확대 도구, 모드와 되돌리기, 한 문장의 모드 설명, 확정 동작으로 구성한다. 계수 영역·번호·사진 교체는 보조 조작이다. 위에 두고 전체 작업 중 보이게 할 개수 요약과 아래 주 동작은 화면 높이가 충분할 때 고정하고, 큰 글꼴/작은 높이에서는 본문 스크롤로 이동한다. 도구를 숨겨 공간을 확보하지 않는다.

완료 화면은 '검수 기록' 제목, 사용자 확인 완료 라벨, 최종 개수/확인 시각, 읽기 전용 사진, 보기 도구, 분리된 기록 삭제다. 새 작업 입력을 제공할 때는 현재 기록을 수정한다는 인상을 주지 않게 '새 사진으로 별도 작업' 맥락을 함께 둔다.

| 레이아웃 토큰 | 초기 설계 | 조정 조건 |
|---|---|---|
| content.inset | 16dp | inset과 중복 가산하지 않음 |
| content.readingWidth | 큰 폭에서 최대 600dp 중심 정렬 | 사진은 사용 가능한 폭을 별도로 평가. 태블릿 지원 완료 주장 아님 |
| section.gap / control.gap | 24dp / 8dp | 글꼴 확대 시 그룹 줄바꿈 |
| summary.number | 40sp/48sp | 단위/상태와 겹치면 행을 분리 |
| photo.default | 가용 높이와 사진 비율에 맞춤, 전체 사진 Fit | 고정 높이보다 단면 식별과 핵심 도구 도달 우선 |
| action.primary | 최소 56dp, 한 화면 상태의 주역 | 길어진 텍스트는 높이 확장 |
| icon.default / icon.target | 24dp / 최소 48dp | 24dp 그림을 24dp 터치 영역으로 사용하지 않음 |

가로 화면은 같은 조작의 순서를 유지하는 스크롤/가능한 사진·도구 나란한 배치를 평가한다. 새 Navigation 목적지나 전역 선택 상태를 추가하지 않는다. 키보드가 필요 없는 현재 흐름에 입력 필드·메모·이름을 디자인 장식으로 넣지 않는다.

## 13. 디자인 운영과 수락 기준

`mobile-android-design`의 Material 기본 컴포넌트·반응형·접근성 기준과 기존 Compose Expert를 함께 사용한다. 일반 예제의 dynamic color, 하단 탭, swipe-to-delete, 모든 원자 컴포넌트 래핑은 이 프로젝트의 요구로 자동 채택하지 않는다. 사용자 결정과 PRD를 우선하며 이 문서가 Pounter의 역할·표현 기준이다.

규칙 변경은 의미/변형/사용 위치/접근성 영향/기존 컴포넌트로 해결 못 하는 이유를 함께 기록한다. 새 색은 역할과 전경/배경 쌍이 필요하고 새 컴포넌트는 반복되는 업무 의미가 필요하다. 변경할 때 시안과 본문 토큰을 동시에 갱신한다. 작은 앱에서 별도 토큰 동기화 도구·디자인 시스템 모듈·범용 컴포넌트 프레임워크는 만들지 않는다.

디자인 보드에는 가상 수동 기록만 사용한다. 12개 표시가 있는 합성 단면 그림은 배치/밀도 설명용이며 검출 성공·실사진·현장 정답이 아니다. 브랜드 아이콘은 기존 첨부의 시각 해석만 반영하고 원본 이미지는 외부 전송하지 않는다.

설계 수락: 토큰 → 컴포넌트 → 상태 → 화면의 연결이 명확하고 실패/완료/미분석을 구별할 것. 구현 수락: 8절 실행 검증과 실제 화면에서의 조작 도달을 확인할 것. 현장 효용 수락: 별도로 PRD의 전체 검수 시간·오류·독립 실사진 평가를 따를 것. 세 수락 상태를 하나의 '완료'로 합치지 않는다.

2026-10-13 시안 검증: 기존 Chrome의 브라우저 렌더링에서 라이트·다크·저장 실패·큰 글꼴 탐색 변형을 확인했다. 360px 폭에서 문서 가로 넘침과 브라우저 스크립트 오류가 없었다. 라이트·다크/실패·작은 폭 캡처를 관찰했다. 브라우저의 px와 확대 표현은 Android dp/sp·글꼴 200%·TalkBack·실기기 검증을 대신하지 않는다. 앱 코드 변경은 없다.
